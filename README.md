# 油站巡检整改交接台

把"巡检发现异常 → 只改状态、口头整改、交班漏项"的旧清单，升级为**登记有责任人与期限、复检不合格不交班、班长确认 + 接班人签收、完成记录冻结留痕**的整改交接台。

- 行业：石油（油站设备巡检）
- 技术栈：React 19、Vite、TypeScript、Zustand、Ant Design
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 数据：保存在浏览器 localStorage（键 `gas-station-rectification-v1`），刷新/重开不丢；可点"恢复演示数据"重置

## 业务规则

1. **登记异常**：必须写清区域、设备、现场说明、责任人、整改期限、登记人；缺项不能提交。
2. **重复异常**：同一设备存在未关闭异常时禁止重复登记（避免覆盖式重报）；待复检合格（关闭）后再次出现，自动记为该设备第 2 次异常，沿同一异常链保留全部前后记录，设备累计异常次数与整改次数分别累加。
3. **整改/复检闭环**：
   - 待整改 / 复检未过 → 提交整改（整改人 + 整改措施，禁止只靠口头）→ 待复检；
   - 复检合格 → 已完成并**冻结**；复检未过 → 退回整改，设备累计整改次数 +1，且**该区域被禁止交班**。
4. **交班**：班长先确认待办并生成冻结快照（同一时刻只允许一张待签收交班单），接班人逐项核对后**签名签收**，签收后成为可复查的历史凭证；存在复检未合格项的区域时系统直接拒绝交班。
5. **冻结与补写**：完成记录不可直接改写；补写/更正必须填写操作人和原因，系统保留改前内容、改后内容与时间，审计痕迹只追加。
6. **查询**：可按设备、区域、状态组合筛选并按关键词检索，筛选条件持久化，重开页面仍可查。

## 分层结构（数据 / 判定 / 存储 / 页面 分离）

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 数据 | `src/data/types.ts`、`src/data/seed.ts` | 领域模型（设备、异常单、复检、交班单、补写痕迹）与初始数据 |
| 判定 | `src/rules/engine.ts` | 纯函数业务规则：登记、整改、复检、交班拦截、签收、冻结补写、查询统计；不依赖 DOM / localStorage / React |
| 存储 | `src/store/repository.ts` | localStorage 读写、容错回退、重置与版本化入口 |
| 应用状态 | `src/store/useAppStore.ts` | Zustand store，编排"规则 → 持久化"，页面只调用动作 |
| 页面 | `src/App.tsx`、`src/pages/**`、`src/utils/format.ts` | 台账页、交班台、登记弹窗、异常详情抽屉与展示格式化 |

判定层为纯函数，可脱离界面独立验证（已用 22 项用例自检，覆盖交班拦截、重复异常计数、冻结补写留痕等）。
